Architecture / Developer Experience

Make a Distributed System Easier to Change

In an environment of two dozen-plus connected applications across cloud and on-premises systems, I spearheaded the move to a monorepo. Nx coordinates builds; pnpm and NuGet central package management consolidate dependencies. Moving internal packages to project references simplifies releases and creates a path to shared pipelines, code, and documentation.

The work includes aligning framework and package versions and tackling difficult upgrades, including IronPython 2 to 3. My architectural direction is simplification: consolidate services into modular monoliths where independent deployment adds more cost than value.

Make Good Delivery Repeatable

I introduced shared agent skills across the organization to help teams adopt AI and use it more effectively. Those skills support a consistent workflow:

  1. Define the product specification.
  2. Translate it into a technical plan.
  3. Review the plan and its tradeoffs.
  4. Have an agent implement the plan.
  5. Review, test, and QA the output.
  6. Ship through deployment pipelines.

Unit and integration tests give agents useful feedback and reviewers evidence. I'm also implementing coverage monitoring and exploring mutation testing to understand how well our tests catch mistakes.

Documentation is part of that environment. I created skills and led an effort to capture architectural decisions, business rules, domain guides, glossaries, inline explanations, and runbooks. System diagrams and Mermaid workflows help connect knowledge spread across applications.

Hands-on with Claude Code, Codex, Copilot, Cowork, and Cursor, including autonomous agent loops and reusable skills.

Engineering Judgment Still Matters

  • Own the outcome. AI writes the code; I own the requirements, architecture, verification, and delivery.
  • Fix the cause. Turn review findings and QA failures into better guidance, tests, and workflows.
  • Reduce the cost of the next change. Inconsistent patterns, unfinished migrations, and missing documentation are technical debt, too.
  • Earn the complexity. Prefer clear boundaries and simpler systems when more services don't improve the product.
